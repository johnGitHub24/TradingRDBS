# TradingRDBS 驗證設計

> 衝突以 [TradingRDBS 規格書.md](../TradingRDBS%20規格書.md) 為準。  
> 規範：EngineeringOS `knowledge/validation-design.md`

## 1. 四層驗證

| 層 | 機制 | 典型失敗 |
|----|------|----------|
| L1 傳輸／認證 | OAuth 2.0 Bearer JWT、`SecurityFilterChain`、`authenticated()` | 401／403 |
| L2 格式 | DTO `@Valid` | 400 `VALIDATION_FAILED` |
| L3 業務 | Service（帳號／標的重複、FK 不存在） | 404／409 |
| L4 資料 | DB UNIQUE／NOT NULL／FK | 應少見（L3 先攔） |

## 2. 認證流程

```text
POST /api/v1/auth/register → 201（可選）
POST /api/v1/auth/login → 200 { token, tokenType, username, roles }
後續：Authorization: Bearer <token>
  → JwtAuthenticationFilter → SecurityContext
```

- 密碼：BCrypt（`app_users` 表，與交易 `accounts` 分離）
- Token：HS256（`app.jwt.secret`、`expiration-ms`）
- Session：STATELESS
- 示範帳：`demo/demo123`、`admin/admin123`（`AuthDataSeeder`）

## 3. 權限矩陣

| 端點 | 公開 | USER | ADMIN |
|------|------|------|-------|
| POST `/api/v1/auth/login`、`/register` | ✅ | — | — |
| Swagger／health／h2-console／靜態 UI | ✅ | — | — |
| `/api/v1/accounts/**`、`/symbols/**`、`/orders/**` | — | ✅ | ✅ |

本專案教學重點在 3NF 關聯，**不**細分 ADMIN 寫入權限；已登入即可 CRUD。

## 4. 錯誤碼

| 情境 | HTTP | 說明 |
|------|------|------|
| 欄位驗證失敗 | 400 | `VALIDATION_FAILED` |
| 帳密錯誤／未帶 token | 401 | `BadCredentialsException`／Security Entry Point |
| 權限不足 | 403 | `AccessDeniedException` |
| 資源不存在 | 404 | account／order not found |
| 使用者名稱重複 | 409 | `UsernameAlreadyExistsException` |

## 5. 對照程式

- Handler：`GlobalExceptionHandler`
- Filter：`JwtAuthenticationFilter`、`JwtTokenProvider`
- Config：`SecurityConfig`、`AuthDataSeeder`
- API：`AuthController`（`/api/v1/auth/**`）
- DTO：`LoginRequest`、`RegisterRequest`、`JwtResponse`
